# Nefro Audit – bezpečnosť a technická optimalizácia

## Popis projektu

Projekt **Nefro** je nefrologická lekárska webová aplikácia (PHP 8.x + MariaDB na WebSupport hostingu). Obsahuje:

- Autentifikáciu a správu používateľov (`auth.php`, `login.php`, `register.php`, `profile.php`)
- 2FA TOTP (`totp.php`, `2fa_setup.php`, `2fa_verify.php`)
- Medicínske kalkulačky (`calculator_*.php`) — eGFR, AKI, ADPKD, CKD-PC, KTV, KFRE a ďalšie
- Administrátorský panel (`admin.php`, `admin_articles.php`, `admin_newsletter.php`, `admin_discussion.php`, `admin_menu.php`)
- Systém článkov (`article.php`, `query_article.php`)
- Newsletter (`newsletter_subscribe.php`, `newsletter_verify_sub.php`, `newsletter_unsubscribe.php`, `newsletter_worker.php`, `newsletter_notifications.php`)
- Diskusiu (`discussion.php`)
- E-mailové a SMS overenie (`email_verification.php`, `mobile_verification.php`)
- SEO infraštruktúru (`sitemap.php`, `head_meta.php`, `generate_og_image.php`)
- Právne dokumenty: Privacy Policy (`privacy.php`), Cookie Policy (`cookies.php`), Podmienky používania (`terms.php`) — spoločný zdroj `legal_data.php`
- CSP reporting (`csp-report.php`)
- Súbory CSS/JS (`index.css`, `nefro-ui.js`, `calculator.js` atď.)

## 🎯 Cieľ agenta

Autonómny agent na komplexnú technickú správu a kontinuálnu optimalizáciu projektu Nefro. ## 📋 Primárne úlohy

### 1. Bezpečnostný audit

- **Skenovanie kódových zraniteľností:**
  - SQL injekcia (nechránené databázové dotazy)
  - XSS útoky (nevhodne escapované výstupy)
  - CSRF ochrana
  - Validácia a sanitácia vstupov
  - Bezpečnosť relácií (session)
  - Kontrola autentifikácie a autorizácie

- **Konkrétne vzory, ktoré treba explicitne hľadať:**
  - **Constant-time porovnanie:** záložné kódy, SMS kódy a iné jednorazové tokeny musia byť
    overované cez `password_verify()` alebo `hash_equals()`, nikdy cez `===` ani `hash('sha256', ...)`
  - **Typ hashu zodpovedá stĺpcu v DB:** `CHAR(64)` = SHA-256 hex; `VARCHAR(255)` = bcrypt —
    nesmiú sa miešať; pri zmene algoritmu treba migrovať aj dĺžku stĺpca
  - **Session fingerprinting pri viacdielovom prihlásení:** pri 2FA `pending` session uložiť
    `pwd_fingerprint = substr(hash('sha256', $password_hash), 0, 16)` a overiť pri 2FA kroku
  - **Pevné okná rate limitingu:** po uplynutí deklarovaného okna resetovať alebo zmazať
    `attempt_count`/`first_attempt`, ale nikdy neskrátiť aktívny `blocked_until`; pokus počítať
    pred drahou validáciou alebo externým volaním, ak by sa nimi dal limit obísť
  - **PRG (Post-Redirect-Get):** každý úspešný POST formulár musí presmerovať pred HTML výstupom;
    chýbajúci PRG = double-submit riziko. **Výnimka — admin stránky (Beh 59):** žiadna `admin_*.php`
    (articles/newsletter/discussion/drugs/trials) PRG nepoužíva — `validateCsrfToken()` v `auth.php`
    **rotuje token po každom POST** (`auth.php:188`), takže refresh re-submit pošle starý token → odmietnutý
    → žiadny double-write. Rovnaká výnimka platí pre kalkulačky, ktoré musia výsledok vykresliť v odpovedi;
    samostatné vedľajšie účinky (mazanie, odoslanie e-mailu/SMS, uloženie profilu) však PRG vyžadujú.
  - **Upload súborov iba po validácii:** súbory sa nesmú nahrávať pred `if (empty($errors))` check;
    veľkosť čítať cez `filesize(tmp_name)`, MIME krížovo overiť cez `getimagesize()` a názov generovať
    kryptograficky. Starý súbor mazať až po úspešnom DB commite, nikdy počas otvorenej transakcie.
  - **Celkový iterácia pri overovaní zoznamu kódov (no early return):** `foreach` cez všetky záznamy
    aj po náleze zhody — predchádza timing útoku pri záložných/SMS kódoch
  - **Samostatné/jednorazové skripty v koreni:** každý skript koreňa, ktorý robí DB zápis/`DELETE`
    (`add_*_article.php`, `refresh_*.php`, `*_migration.php`, `setup_db.php`), musí mať na začiatku
    guard `if (php_sapi_name() !== 'cli') { require auth.php; requireAdmin(); }` — inak je to
    neautentifikovaný destruktívny web endpoint (refresh_article.php ho nemal — Beh 23)
  - **TLS verzia pri odchádzajúcich spojeniach (SMTP/API):** `stream_socket_enable_crypto()` nesmie
    používať `STREAM_CRYPTO_METHOD_TLS_CLIENT` — tá v PHP povoľuje aj deprecated TLS 1.0/1.1 (RFC 8996).
    Vynútiť `STREAM_CRYPTO_METHOD_TLSv1_2_CLIENT | STREAM_CRYPTO_METHOD_TLSv1_3_CLIENT`. Jediný SMTP
    klient je `email_verification.php` (opravené Beh 32). cURL klienti (Twilio) majú `SSL_VERIFYPEER=true`

- **Audit súborov s vysokým rizikom:**
  - `auth.php`, `login.php`, `register.php` — autentifikácia
  - `totp.php`, `2fa_setup.php`, `2fa_verify.php` — 2FA TOTP logika
  - `db_config.php` — databázová konfigurácia
  - `email_verification.php`, `mobile_verification.php` — overenie identity
  - `avatar_upload.php` — nahrávanie súborov
  - `csp-report.php` — limit tela, whitelist/redakcia reportu, atomický rate limit, bezpečné práva
    súborov, retenčný cleanup a fail-closed odpoveď pri zlyhaní zápisu
  - Všetky API koncové body (endpointy)

### 2. Analýza kódu

### 3. Kontrola kvality kódu

- Konzistentnosť kódovacieho štýlu
- Duplicitný kód a refaktorovateľné časti
- Funkcie s prílišnými parametrami alebo nadmernou komplexitou
- Veľkosť funkcií a cyklomatická komplexita
- Dodržiavanie osvedčených postupov
- **Poznámka:** projekt zámerne nepoužíva komentáre (okrem non-obvious WHY) — nehlasovať ich absenciu ako nález
- **CSP-kompatibilné šablóny:** enforcing politika blokuje inline `style=""`, `<style>`, inline
  `<script>` bez nonce, atribúty `on*=` aj `javascript:` URL. Kontrolovať všetkých päť vzorov,
  nie iba `style=`; štýly patria do `index.css`, správanie do spoločného JS alebo nonce skriptu.
  Výnimka: **e-mailové HTML** inline štýly MUSÍ mať — mail klienti CSP neaplikujú.

### 4. Databázová bezpečnosť

- Prevencia SQL injekcie — hľadanie reťazcovej konkatenácie v SQL dotazoch v PHP kóde
- Kontrola používania pripravených dotazov (PDO `prepare`/`execute`) vs. priamej konkatenácie
- Validácia databázových vstupov
- Audit databázových skriptov (`setup_db.php`)
- Správa údajov relácií

### 5. Kontrola kódovania (súbory + databáza)

- Overenie, že textové súbory používajú platné UTF-8 (ideálne bez BOM)
- Detekcia poškodených znakov (mojibake), neplatných bajtových sekvencií a nekonzistentného kódovania
- Kontrola databázového kódovania a kolácií **statickou analýzou PHP kódu** (nie živými DB dotazmi):
  - Overenie `charset=utf8mb4` v pripojení v `db_config.php`
  - Kontrola `CREATE TABLE` / `ALTER TABLE` v `setup_db.php` — musia používať `utf8mb4`
  - Konzistentná kolácia (napr. `utf8mb4_unicode_ci`)
- Pri náleze problému navrhnúť bezpečný migračný postup (bez straty dát)

### 7. Jazyková korektúra a kontrola kódovania databázového obsahu

Pokrýva **skutočný obsah uložený v databáze** — nie kód ani UI šablóny.

#### Prístup k obsahu

- Hľadať SQL dump súbory (`*.sql`) v adresári projektu a čítať ich priamo
- Čítať exportované obsahové súbory (`.csv`, `.json`, `.txt`) ak existujú
- Ak dump ani export neexistuje, vypísať zoznam tabuliek a stĺpcov na manuálnu kontrolu cez admin rozhranie

#### Tabuľky s textovým obsahom na kontrolu

| Tabuľka            | Stĺpce na korektúru                                                               |
| ------------------ | --------------------------------------------------------------------------------- |
| `articles`         | `title`, `excerpt`, `content`, `author`                                           |
| `users`            | `name_note`, `organization`, `job_function`, `address_note` — voľné textové polia |
| `discussion_posts` | `content` (príspevky v diskusii)                                                  |

#### Slovenská jazyková korektúra obsahu (DB-SK)

- Gramatika, pravopis, diakritika, typografia (úvodzovky „…", pomlčky –, …)
- Medicínska terminológia — konzistentnosť s UI a kódovou základňou
- Štýlová jednotnosť naprieč článkami (oslovovanie, slovosled, odbornosť)
- Zachovať odborný obsah — opravovať len jazykové chyby, nie fakty

#### Kontrola kódovania obsahu (DB-KÓD)

- Detekcia mojibake (napr. `Ã¡` miesto `á`, `Ä\x8d` miesto `č`)
- Hľadanie neplatných UTF-8 bajtových sekvencií v textových poliach
- Kontrola HTML entít v čistom textovom obsahu (`&amp;`, `&lt;`, `&nbsp;` — ak sa vyskytujú mimo HTML kontextu, sú chybné)
- Kontrola nekonzistentného kódovania medzi rôznymi článkami (naznačuje importy z rôznych zdrojov)
- Pri náleze mojibake navrhnúť SQL opravu pomocou `CONVERT(BINARY CONVERT(pole USING latin1) USING utf8mb4)`

#### Výstup

Každú nájdenú chybu reportovať s kódom `DB-SK-n` (jazyková) alebo `DB-KÓD-n` (kódovanie), názvom tabuľky, ID záznamu a konkrétnym návrhom opravy.

### 9. Komplexná SEO optimalizácia a integrita kódu

- Analýza a dopĺňanie metadát (titulky, popisky, kanonické URL, Open Graph)
- Generovanie a údržba štruktúrovaných dát (JSON-LD) a sitemap súborov
- Kontrola platnosti interných odkazov a konzistencie projektu (vrátane opravy nefunkčných)
- **Overovanie externých odkazov (obmedzený sandbox):** sieťový egress je filtrovaný → HTTP `000`
  (Could not resolve host) NIE je dôkaz mŕtveho odkazu a `403` je zvyčajne anti-bot (živé, napr.
  NEJM/JAMA/lww — nechať). **Ground truth = DNS-over-HTTPS** (`dns.google/resolve` + Cloudflare):
  Status 3 = NXDOMAIN = reálne mŕtva doména (odstrániť), Status 0 = žije. `404` (server odpovedal) =
  spoľahlivá chýbajúca cesta. 404 vzdelávacie podstránky národných spoločností → fallback na overenú
  hlavnú doménu; presunuté org majú často novú doménu (ifkf-wka.org→ifkf.org, munuaisjamaksaliitto.fi→muma.fi) — Beh 34;
  **ďalšie potvrdené presuny/opravy (Beh 66):** `annuk.org`→`ann-uk.org` (nesprávna doména ANN-UK), `csn-scn.ca`→`csnscn.ca`
  (kanonická; `/education/`→`/_education/`), `uoou.sk`→`dataprotection.gov.sk` (mŕtvy, SK úrad na ochranu OÚ), `www.bvnv.be`
  (expirovaný cert) → `bvnv.peepl.be/nl/site/`, `clinicaltrials.ucsf.edu` (mŕtva subdoména) → `clinicaltrials.gov`, MDCalc `/calc/3886` (404,
  kalkulačka zrušená → odkaz odstránený). **Metóda (prostredie má curl + WebFetch):** `403`/timeout renomovaných vydavateľstiev
  (AJKD/NEJM/JAMA/doi.org/Mayo) = anti-bot, NIE mŕtve — nechať; reálne mŕtve = reset/NXDOMAIN/404 potvrdené ≥2 nástrojmi. Oprava
  linku v `legal_data.php` (dozorný úrad) NEbumpuje `version` (nie je podstatná zmena → nerozosielať e-mail). Zmena odkazu v tele
  publikovaného článku = 3 kroky (edit `add_*` → SSH UPSERT → `sync_article_pdfs.sh`), lebo obsah je v DB.
- **Úplnosť `sitemap.php`:** každá nová verejná stránka/kalkulačka/nástroj musí pribudnúť aj do `sitemap.php`.
  Over zhodu zoznamu kalkulačiek v `calc_subnav.php` (kanonický zoznam) vs. `sitemap.php` — výnimka
  je len `calculator_history.php` (za loginom + `Disallow` v `robots.txt`). PREVENT chýbal — Beh 32;
  cystatín C — Beh 52. **Rozšírené (Beh 53):** cross-check aj `nastroj_*.php` (hub `nastroje.php`)
  a obsahové huby `populars.php`/`podpora.php` — žiadny `noindex`/`Disallow` ⇒ patrí do sitemap.
  Rýchla kontrola: každá `*.php` bez `noindex` a bez `Disallow` v `robots.txt`, ktorá je v navigácii/pätičke,
  musí byť v `sitemap.php`.
- **Inverzná kontrola admin stránok (Beh 58):** každá samostatná `admin_*.php` (vlastný `<!doctype>` + `requireAdmin()`)
  patrí do `robots.txt` Disallow — recidíva: nová `admin_*.php` pridaná s `noindex`+`requireAdmin`, ale zabudnutá v
  `robots.txt` (`admin_drugs_review.php` — Beh 58). Include fragmenty (`admin_menu.php`, bez doctype) sú výnimka.
  Deterministicky: `for f in admin_*.php; grep -q doctype $f && grep -q requireAdmin $f && grep -q "/$f" robots.txt`.

### 10. Kontrola responzívneho dizajnu

- Overenie všetkých `@media` breakpointov (480px, 600px, 768px, 960px, 1024px)
- **Krížová konzistencia breakpointov:** hamburger menu a layout grid musia mať rovnaký breakpoint
  (v projekte historická chyba: hamburger @1024px, grid @960px — vždy overiť zhodnosť)
- Kontrola pretekania obsahu (`overflow-x: hidden` → má byť `auto` pri scrollovateľnom obsahu)
- Audit `min-width` hodnôt v komponentoch (pevné šírky môžu spôsobiť horizontálny scroll)
- Kontrola navigácie, formulárov, tabuliek a kalkulačkových komponentov na mobile
- Overenie `touch-target` veľkosti tlačidiel (min. 44×44 px) pre mobilné zariadenia;
  pre admin akcie stačí 32px (vedľajšie interné prvky)
- Kontrola `clamp()`, `vw` a `auto-fit` grid hodnôt pre plynulé škálovanie
- Testovanie header-profile, auth-container a admin panelov na úzkych displejoch
- Oprava identifikovaných problémov priamo v `index.css`

### 11. Hĺbková kontrola prístupnosti (Accessibility / WCAG 2.1 AA)

Cieľový štandard: **WCAG 2.1 úroveň AA** (záväzná v EÚ podľa smernice 2016/2102 a EN 301 549).
Agent kontroluje statickou analýzou HTML/PHP/CSS — bez spúšťania prehliadača.

#### Perceivable (Vnímateľnosť)

- **Alt texty:** každý `<img>` musí mať `alt`; dekoratívne obrázky `alt=""`; avatary zmysluplný popis
- **Farebný kontrast:** text vs. pozadie min. 4,5:1 (normálny), 3:1 (veľký ≥18pt/14pt tučný); overenie hexadecimálnych farieb v `index.css`
- **Nepoužívať farbu ako jediný nosič informácie** (napr. červená = chyba musí mať aj ikonu/text)
- **Adaptovateľnosť:** obsah musí byť čitateľný bez CSS; tabuľky majú `<th scope>`, formuláre `<label for>`
- **Médiá:** ak sú videá/audia, musia mať titulky alebo prepis

#### Operable (Ovládateľnosť)

- **Klávesová navigácia:** všetky interaktívne prvky dostupné cez Tab; žiadne klávesové pasce
- **Skip link:** `<a href="#main-content" class="skip-link">Preskočiť na obsah</a>` ako prvý element v `<body>`
- **Viditeľný focus:** `:focus` štýl nesmie byť `outline: none` bez náhrady; skontrolovať v `index.css`
- **Touch target:** min. 44×44 px pre mobilné prvky (admin: 32 px — pozri sekciu Responzívny dizajn)
- **Časové limity:** ak existujú session timeouty, používateľ musí byť upozornený pred vypršaním
  a musí mať dostupné predĺženie bez straty rozpracovaného formulára; keepalive nesmie rotovať
  globálny formulárový CSRF token

#### Understandable (Zrozumiteľnosť)

- **Jazyk stránky:** `<html lang="sk">` na každej stránke
- **Jazyk časti:** ak je text v inom jazyku, `lang` atribút na príslušnom elemente
- **Konzistentná navigácia:** rovnaké prvky na rovnakých miestach naprieč stránkami
- **Identifikácia chýb:** každé chybové hlásenie formulára musí identifikovať konkrétne pole (`aria-describedby`, `role="alert"`)
- **Labely a inštrukcie:** všetky polia formulára musia mať viditeľný label alebo `aria-label`

#### Robust (Robustnosť)

- **Validita HTML:** kontrola `id` unikátnosti, uzatvárania tagov, zákazu `<div>` vo `<table>`
- **ARIA správnosť:**
  - `role`, `aria-label`, `aria-labelledby`, `aria-describedby` — overenie správneho použitia
  - `aria-hidden="true"` nesmie skrývať fokusovateľné prvky
  - `aria-expanded`, `aria-current`, `aria-live` — prítomnosť na dynamických komponentoch
- **Sémantické HTML:** nadpisy tvoria logickú hierarchiu (H1→H2→H3, žiadne preskočenie)
- **Formuláre:** `autocomplete` atribúty (napr. `email`, `new-password`, `given-name`) pre asistívne technológie
- **Samostatný `<select>` bez `<label for>`** (typicky prepínač jednotiek vedľa labelovaného inputu — `uacr_unit`, `chol_unit`) musí mať `aria-label` (WCAG 4.1.2; recidíva naprieč kalkulačkami — Beh 31)

#### Špecifiká projektu

- Kalkulačky: výsledky musia byť oznámené cez `role="status"` alebo `aria-live="polite"`
- Modálne okná / rozbaľovacie menu: fokus management, `aria-modal`, Escape na zatváranie
- Tabuľky v admin paneli: `<caption>` alebo `aria-label`, `scope="col/row"` na hlavičkách

#### Implementácia a oprava

Agent **implementuje** nájdené problémy priamo (ARIA atribúty, skip link, label opravy, focus štýly v CSS).
Zmeny rozsahu viac ako 5 súborov vyžadujú súhlas.

### 13. Cookie Banner — funkčnosť, náležitosti a súlad

#### Existencia a základná funkcionalita

- Overenie, či cookie banner existuje v kóde (hľadať v `header.php`, `footer.php`, `index.css`, JS súboroch)
- Ak neexistuje → **implementovať** (povinné podľa ePrivacy smernice a § 55 ods. 5 zákona č. 351/2011 Z. z.)

#### Požiadavky na súhlas (opt-in pre nekritické cookies)

- **Technicky nevyhnutné cookies** (session, CSRF, uloženie voľby súhlasu): bez súhlasu — OK;
  trvalá téma a história kalkulačiek patria medzi preferenčné úložisko a vyžadujú opt-in
- **Analytické cookies** (Google Analytics / GTM): vyžadujú **explicitný opt-in pred nastavením**
- **Marketingové cookies** (ak existujú): vyžadujú opt-in
- Overenie, že GA/GTM skripty sa načítajú **až po udelení súhlasu**, nie pred

#### Náležitosti bannera

- Jasný, zrozumiteľný text v slovenčine — čo sú cookies a na čo slúžia
- Minimálne dve možnosti: **„Prijať"** a **„Odmietnuť"** (alebo „Len nevyhnutné")
- Odkaz na Privacy Policy / Cookie Policy priamo z bannera
- Granulárne nastavenia (voliteľné, ale odporúčané): kategórie Nevyhnutné / Analytické / Marketingové
- **Žiadne predvolené zaškrtnuté políčka** pre nekritické kategórie

#### Persistencia a odvolanie súhlasu

- Súhlas uložený do cookie/localStorage s expiráciou (max. 12 mesiacov odporúčané, max. 13 mesiacov povolené)
- Pri opakovanej návšteve banner sa nezobrazuje, ak je súhlas uložený a platný
- Možnosť **odvolať súhlas** kedykoľvek (odkaz v päte stránky alebo v Privacy Policy)
- Otvorený modal musí ponúknuť priamu jednoklikovú voľbu „Odmietnuť voliteľné“, nielen vypínanie
  jednotlivých prepínačov; odvolanie musí byť rovnako jednoduché ako udelenie
- Pri odvolaní: GA/GTM cookies vymazať alebo deaktivovať

#### Zoznam cookies

- V Privacy Policy alebo Cookie Policy musí byť tabuľka všetkých nastavovaných cookies:
  `Názov | Typ | Poskytovateľ | Účel | Expirácia`

#### Implementácia ak chýba

Agent implementuje jednoduchý cookie banner ak neexistuje:

- HTML/CSS banner v `header.php` alebo ako samostatný include
- JS logika (s nonce) pre ukladanie súhlasu a podmienené načítanie GA
- Aktualizácia Privacy Policy o zoznam cookies
  Implementácia bannera **nevyžaduje súhlas** (ide o právnu povinnosť), ale agent informuje o každej zmene.

### 14. Audit popularizačných článkov pre pacientov (sekcia „Pre pacientov")

Pokrýva články s `category = 'popularne'` (zoznam [populars.php](populars.php),
zobrazenie cez [article.php](article.php)). Tieto články sú určené **poučeným
laikom a verejnosti**, preto majú iný jazykový register a iné nároky než odborné
články. Audituje sa pri každom behu, ak v DB existujú popularizačné články.

#### Prístup k obsahu

- Cez SQL dump / export (rovnako ako [task 7](#7-jazyková-korektúra-a-kontrola-kódovania-databázového-obsahu)), filter `WHERE category = 'popularne'`
- Ak dump neexistuje, vypísať zoznam slugov populárnych článkov na manuálnu kontrolu cez `article.php?slug=…`

#### Jazyková a štýlová revízia (slovenčina pre laika)

- Gramatika, pravopis, diakritika, typografia (úvodzovky „…", pomlčky –) — ako DB-SK
- **Zrozumiteľnosť pre laika**: krátke vety, jednoduchý slovosled, žiadny zbytočný žargón
- **Vysvetlenie skratiek a odborných pojmov** — každá skratka (CKD, eGFR, dialýza…) musí byť aspoň raz vysvetlená ľudskou rečou; ak nie je → nález
- Konzistentné **oslovovanie** (vykanie), priateľský, nepovyšujúci tón — laika neponižovať ani „nepoučovať zhora"
- Terminologická konzistentnosť s odbornými článkami (ten istý pojem = to isté slovo)
- Zachovať **medicínsku správnosť** — opravovať jazyk, nie fakty; pri pochybnosti o fakte → manuálne posúdenie

#### Obsahové a štrukturálne náležitosti

- Obsah **nezačína `<h2>` zhodným s titulom** (duplikát; titul sa generuje automaticky)
- **Prvý `<img>`** v obsahu existuje a má zmysluplný `alt` (slúži ako náhľad karty + prístupnosť)
- Obrázky používajú `loading="lazy"`, relatívnu cestu `img/…`, a existujú v `img/` (nie mŕtve odkazy)
- Prítomné **upozornenie**, že obsah nenahrádza vyšetrenie/konzultáciu u lekára
- `excerpt` je vyplnený, čistý text, ~120–220 znakov
- Externé odkazy majú `target="_blank" rel="noopener noreferrer"`

#### Výstup

Každý nález reportovať s kódom `POP-n`, slugom (alebo ID) článku a konkrétnym návrhom opravy. Jazykové opravy textu sú triviálne (autoopravy); zásahy meniace faktický obsah vyžadujú súhlas.

## 🔁 Self-Improvement Loop

> **Povinný posledný krok každého behu.** Agent berie tento súbor ako živý nástroj
> a po každom audite ho zostruje. Cieľ: každý beh je rýchlejší, zachytí viac reálnych
> problémov a vytvorí menej šumu než predchádzajúci.

Po dokončení auditu a opráv agent **musí**:

1. **Zaznamenať poučenia** — doplniť do [Poučenia z predchádzajúcich auditov](#-poučenia-z-predchádzajúcich-auditov):
   - Každú **novú** triedu chyby alebo koreňovú príčinu objavenú v tomto behu.
   - Každý **falošný poplach**, ktorý zožral čas — aby sa rovnaký šum nezopakoval.
   - Každú **opravu, ktorá niečo pokazila** (a správny postup) — aby sa chyba neopakovala.

2. **Spresniť kontroly** — upraviť príslušnú sekciu Primárnych úloh:
   - Ak reálny problém nemal zodpovedajúcu kontrolu, pridať konkrétnu kontrolu.
   - Ak kontrola naprieč viacerými čistými behmi nikdy nezareaguje, znížiť jej prioritu alebo ju zlúčiť.
   - Opakujúce sa bezpečné opravy povýšiť do zoznamu „Triviálne opravy".

3. **Prerezať a deduplikovať** — tento súbor je nástroj, nie changelog:
   - Každá sekcia musí ostať prehľadná. Odstrániť zastarané kontroly.
   - Nikdy nedovoliť, aby sekcia prerástla to, čo sa dá prečítať za ~30 sekúnd.

4. **Aktualizovať metadáta** — bumpnúť dátum v pätičke a počítadlo behov.

### Mantinely self-improvementu

- **Skôr zostriť než pridať.** Ak súbor rastie, v tej istej úprave niečo zastarané prerež.
- **Konkrétne nad všeobecné.** „Over `consentVersion` sync medzi legal_data.php a ui-preferences.js" je lepšie než „zlepši GDPR".
- **Podložené dôkazom.** Pridať len kontrolu, ktorú odôvodňuje reálny nález (tento beh alebo zdokumentovaný minulý). Nešpekulovať.
- **Nikdy neoslabuj bezpečnosť.** Self-improvement smie sprísniť zoznam „vyžaduje súhlas", ale nesmie presunúť rizikovú akciu do auto-opráv bez preukázanej bezpečnosti v ≥2 behoch.

## ⚠️ Nástroje a obmedzenia

**POVOLENÉ a ODPORÚČANÉ (plný shell — PowerShell aj Bash, PHP 8.3 CLI, git):**

- **`php -l` lint celého repa** — spustiť na začiatku každého behu (`for f in *.php; do php -l "$f"; done`),
  zachytí syntaktické chyby, ktoré statický grep minie; rýchle a deterministické
- **IDE diagnostika (SonarPHP/SonarLint)** sa po každom `Edit` vracia cez hook ako `<ide_diagnostics>` —
  čítať ju: odhalila reálne nálezy (napr. slabý TLS protokol, dead premenné). Bezpečnostné kódy
  (S4423 protokol, S2076/S2078 injection, S5042) brať vážne; štýlové (S1192 literály, S3776
  komplexita, S1488) sú šum — nehlásiť
- **PHPStan (PHAR, level 4 + baseline)** — `php tools/phpstan.phar analyse --no-progress`; baseline (`phpstan-baseline.neon`) hlási len NOVÉ chyby nad existujúcim kódom. Spustiť pri každom behu dotýkajúcom sa PHP logiky — deterministickejší než SonarPHP. **PHP-CS-Fixer** (`php tools/php-cs-fixer.phar fix --dry-run --diff`) na štýl — aplikovať len so súhlasom (typicky >5 súborov). Inštalácia: `tools/install-dev-tools.ps1` (PHAR, bez Composera). Pozn.: `/** @var \PDO $pdo */` za `require db_config.php` je zámerné (PHPStan nevidí premenné cez include) — neodstraňovať.
- Čítanie/zápis súborov, statická analýza, grep vzory, automatické opravy
- Git commit/push do `main`, deploy cez hook (pozri Bezpečnostné nastavenia)

**Stále ZAKÁZANÉ:**

- Živé DB dotazy proti produkcii (kontrola kódovania/kolácie sa robí statickou analýzou PHP)
- `git reset --hard`/`push --force` a iné deštruktívne git operácie bez explicitného súhlasu
- Spúšťanie `setup_db.php`/migračných skriptov proti produkčnej DB
